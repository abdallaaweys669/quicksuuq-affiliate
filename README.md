# QuickSuuq Affiliate System — Next.js + Supabase Foundation

This project moves the affiliate backend from a separate Express service into **Next.js Route Handlers**. Supabase provides managed PostgreSQL. The React Native app is out of scope for this phase.

## Included

- Next.js App Router application shell
- `POST /api/webhooks/shopify` for Shopify `orders/paid`, `orders/cancelled`, and `refunds/create`
- Raw-body Shopify HMAC verification and expected-store validation
- Supabase PostgreSQL schema for salespeople, customer mappings, commissions, refunds, payouts, payout allocations, and webhook event records
- Phone normalization for common Somali formats (e.g. `0615551234`, `615551234`, `+252615551234`)
- First valid referral attribution by phone; an existing mapping wins on future orders
- Unique Shopify order and refund IDs to protect against duplicate webhook deliveries
- `/api/health` database connectivity check

## 1. Requirements

- Node.js 20+
- A Supabase project
- A Shopify app with the correct webhook subscriptions and webhook signing secret

## 2. Configure environment

Copy `.env.example` to `.env.local` and set:

- `DATABASE_URL`: Supabase PostgreSQL connection string. Use a connection mode suitable for the hosting runtime; verify networking/IPv4 compatibility for your Supabase plan and Vercel setup.
- `SHOPIFY_API_SECRET`: Shopify app client secret used to verify webhook signatures.
- `SHOPIFY_STORE_DOMAIN`: exact `*.myshopify.com` domain from the webhook header.

Never prefix secrets with `NEXT_PUBLIC_`, commit `.env.local`, or paste credentials into AI prompts/logs.

## 3. Create the database schema

In Supabase, open **SQL Editor**, paste `supabase/schema.sql`, and run it. The schema enables RLS on tables and defines no public policies. The server connects through `DATABASE_URL`; never expose this connection string to browsers.

Create a salesperson test row in SQL Editor, for example:

```sql
insert into public.salespeople (name, code, commission_rate)
values ('Ali Mohamed', 'ALI100', 0.02);
```

Do not insert real customer phone numbers into test data.

## 4. Run locally

```bash
npm install
cp .env.example .env.local
npm run dev
```

Open `http://localhost:3000`. Check `http://localhost:3000/api/health` after configuring the database.

## 5. Shopify webhook setup

Register these HTTPS webhook subscriptions to:

`https://YOUR_DEPLOYMENT_DOMAIN/api/webhooks/shopify`

- `orders/paid`
- `orders/cancelled`
- `refunds/create`

Use the Shopify app's webhook signing secret in `SHOPIFY_API_SECRET`. Confirm the configured scopes and subscriptions in Shopify Admin. Send test webhooks first; do not test against live customer orders initially.

### Important phone-capture caveat

This code checks `order.phone`, shipping/billing phone fields, and explicitly named phone attributes in `note_attributes`. It does **not** assume Shopify automatically copies the checkout phone into note attributes. Verify the actual order payload generated by your storefront and ensure your checkout/cart flow collects the phone reliably. Orders without a valid phone are not lifetime-mapped.

## 6. Commission behavior

- Commission uses the available current subtotal, falling back to subtotal, and excludes shipping/tax when those Shopify fields are as expected.
- Existing phone mapping takes precedence over a later referral code.
- A valid first referral maps the phone permanently to the salesperson.
- Duplicate paid-order deliveries do not create duplicate commission rows.
- Refunds are recorded once per Shopify refund ID and reduce eligible commission using refunded line-item subtotals.
- Manual refunds with no refund line items may not provide enough detail for automatic commission adjustment; reconcile these in Shopify Admin.
- A cancellation voids unpaid commission. If commission was already paid, the code reports that manual reconciliation is required rather than silently rewriting payout history.

## 7. Before production

This is a **backend foundation**, not a production-complete affiliate product. Do not expose it to real salespeople yet. Before launch, implement and test:

1. Admin and salesperson authentication (prefer Supabase Auth, not a custom plaintext PIN login).
2. Server-side authorization on every protected route and salesperson scoping by authenticated identity.
3. Admin management routes for salespeople and commission approvals.
4. Payout creation in a database transaction that allocates commissions exactly once.
5. Webhook inbox/retry monitoring and reconciliation for out-of-order events.
6. Rate limiting, audit logging without PII, secure headers, and operational alerts.
7. Correct handling of currencies, manual refunds, disputes, chargebacks, and commission rules.
8. End-to-end tests against Shopify development/test orders and an access-control review.

The current dashboard is intentionally a status shell. It does not expose commission/customer data or provide login until authorization is implemented.
